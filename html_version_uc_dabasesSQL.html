    ¿What is a database?

    A database is an organized collection of data. It is the collection of tables, queries, reports, views and other subjects. The data is typically organized to model aspects of reality in a way that supports processes requiring information.
    You can represent data or retrieve data, depending in models thata requiere availability.
    We you store data you must have a way to retrieve it, so storage is critical.

    When you book a flight ticket, you'll need this information:

    FirstName LastName Age Booking/itin ID Phone

A **calculated column** might be a third column based in other two pre-existed columns where against we made some operations. ```query6 use AdventureWorksLT2025 --st12 select Name, ListPrice from [SalesLT].[Product] select Name, ListPrice, ListPrice + 15 as Price_increment from [SalesLT].[Product] /*In this instance we are adding 15 units to the price of column ListPrice and getting it into our table*/ ``` To store a calculated column into a table we will use a **into** clause. ```query7 select Name, ListPrice, ListPrice + 15 as Price_increment into [SalesLT].[customtable01] from [SalesLT].[Product] /*To store a calculated column into a table we will use a **into** clause we'll insert into a logic an the container table will be created in the database we are currently wonking on*/ ``` after refreshing out `Object Explorer window` we'll be able to see the recently created table, output. There are three main Join types: * Inner join * Outer join * Cross join ### Inner join For example, we could have these two tables: | EmployeeID|FirstName|LastName| |---|---|---| |1|Michael|Scott| |2|Pam|Beesly| |3|Dwight|Shrute| | EmployeeID|Salary| |---|---| |1|10000| |2|8000| |3|6000| Now let's imagine we need All the employees, their first and last name, and their salary. In *inner joins* we will only get the records that exist in both tables, there should be atleast 1 match between both the tables. ### Outer joins |EmployeeID|FirstName|LastName| |---|---|---| |1|Michael|Scott| |2|Pam|Beesly| |3|Dwight|Shrute| |EmployeeID|Salary| |---|---| |1|10000| |2|8000| |3|6000| |EmployeeID|PhoneNumber| |---|---| |1|121-112-3342| |2|111-111-1111| As an example I will create this three tables in MSST, this query will create the first table: ```creating employees1 use mytestdb create table dbo.employees ( EmployeeID varchar(50), FirstName varchar(50), LastName varchar(50) ) ``` Inserting values into table: ```inserting into employees1 insert into dbo.employees(EmployeeID, FirstName, LastName) values(1,'Michael','Scott') insert into dbo.employees(EmployeeID, FirstName, LastName) values(2,'Pam','Beesly') insert into dbo.employees(EmployeeID, FirstName, LastName) values(3,'Dwight','Shrute') ``` The second table was made in one execution: ```table salary --table salary use mytestdb create table dbo.salary ( EmployeeID varchar(50), Salary int ) insert into dbo.salary(EmployeeID, Salary) values(1,'10000') insert into dbo.salary(EmployeeID, Salary) values(2,'8000') insert into dbo.salary(EmployeeID, Salary) values(3,'6000') select * from dbo.salary ``` This was the syntax of the creation of the third table: ```table Phone Number --table phone number use mytestdb create table dbo.PhoneNumber ( EmployeeID varchar(50), PhoneNumber varchar(50) ) insert into dbo.PhoneNumber(EmployeeID, PhoneNumber) values(1,'121-112-3342') insert into dbo.PhoneNumber(EmployeeID, PhoneNumber) values(2,'111-111-1111') select * from dbo.PhoneNumber ``` Outer joins should get all the data even there is no data in the third join. ### Left outer joins What happens when I left join employees table with table phone number.
